# Troubleshooting Log

## Incident 001: ORA-01031 During Table Creation

**Date:** October 2026

**Environment:** Oracle AI Database 26ai Free, Docker Desktop, Windows 11, Oracle SQL Developer

**Affected schema:** `SIS`

**Category:** Database privileges and schema setup

### 1. Problem

While executing `sql/03_create_tables.sql` as the `SIS` user, Oracle returned:

- `ORA-01031: insufficient privileges` while creating `DEPARTMENTS` and other tables.
- `ORA-00942: table or view does not exist` while creating tables that referenced tables that had failed to be created.

### 2. Investigation

The first error was treated as the primary failure because it occurred while creating the first table. The later errors were investigated as possible consequences of the initial failure.

The investigation focused on the privileges available to `SIS`, particularly the privileges required by the identity-column definitions:

```sql
GENERATED BY DEFAULT AS IDENTITY
```

Identity columns use Oracle's sequence-generation mechanism. The `SIS` user needed the `CREATE SEQUENCE` privilege in addition to the required table-creation privileges.

### 3. Root Cause

The `SIS` user did not have all the required privileges to create the tables with identity columns.

Because `DEPARTMENTS` was not created successfully, subsequent table definitions that referenced it or other missing tables also failed.

### 4. Resolution

Connected using the administrative account and granted the missing privilege to `SIS` in the correct pluggable database:

```sql
GRANT CREATE SEQUENCE TO SIS;
```

Then verified the effective privileges and retried the table creation script.

### 5. Verification

Confirmed that the tables were created successfully in the `SIS` schema.

The following query can be used to verify the schema objects:

```sql
SELECT table_name
FROM user_tables
ORDER BY table_name;
```

### 6. Lessons Learned

- Investigate the earliest error before addressing subsequent failures.
- SQL statements may require privileges for dependent database features, not just their primary operation.
- Identity columns use sequence generation to produce identifiers.
- Verify the connected user and pluggable database before changing privileges.
- Apply the least-privilege principle instead of granting broad administrative access.
- Test a corrected statement before rerunning an entire DDL script.
- Record the error, root cause, corrective action, and verification results for future troubleshooting.

### 7. Follow-Up

- Confirm that all 10 project tables exist.
- Inspect constraints and indexes.
